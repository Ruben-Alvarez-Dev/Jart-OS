# Core Principles

## P1 — Structure before scale
Jart-OS prefers explicit architectural boundaries before feature accumulation.

## P2 — One system, not many fragments
The system should behave as a coherent operational whole, not as a random collection of services.

## P3 — Host-aware by design
Some capabilities belong close to the machine. Others belong inside the platform bubble. The architecture must respect that distinction.

## P4 — Self-contained services
Every service should own its compose definition, configuration, persistent data, and operational context.

## P5 — Documentation must match reality
A powerful system without a coherent narrative becomes hard to maintain. Public documentation must explain the architecture clearly and truthfully.

## P6 — Public canon, private workshop
The public repository defines the canonical architecture. Private workspaces may contain raw history, drafts, and sensitive material, but the public repo must stay curated.

## P7 — English everywhere in the repository
All repository-facing documentation, naming, and structure must remain in English.
